# 注释规范

*：该写的必须写，不该写的一条都不写。判断标准是——注释描述**代码长期成立的事实**，不是本次改动的过程。
适用于代码、配置、脚本和文档中的注释（`//`、`#`、`<!-- -->` 等）。

注释要**少而准*

## 应该写

- 非显然的约束、边界条件、失败模式
- 与外部协议、格式、字段对应的原因
- 绕过某个坑的理由，以及不能随便改的地方
- 模块或复杂函数的整体意图
- 压制型语句的理由与移除条件：`@ts-expect-error`、`eslint-disable`、`as any`、`@ts-ignore` 必须写明为什么需要，以及在什么条件下可以删除

## 不要写

- 计划性、过程性注释：`// Step 1`、`// TODO: 后面再补`、`// 按方案实现`、`// 先这样`、`// 接下来做 X`
- 复述代码本身的注释：`// 设置 name`、`// 遍历数组`
- 与当前代码无关的说明、任务清单、PR 描述式内容
- 被注释掉的旧代码（直接删除，历史在 Git 里）
- 为了"看起来有注释"而加的填充注释

## 公共 API 与 TODO

- `packages/*` 的导出符号使用 TSDoc，说明协议语义、不变量和兼容性约束；公共注释是契约的一部分。
- TODO 只允许带归属和退出条件的形式，例如 `TODO(#123): 原因 + 移除条件`。无主 TODO 视为坏注释。

## 维护

- 改实现时同步改注释；过时注释按缺陷处理，不按文档处理。
- 注释默认用中文，除非该文件已有明确的英文注释风格。
