# 注释规范

适用于代码、配置、脚本和文档中的注释（`//`、`#`、`<!-- -->` 等）。

注释要**多而干净**：解释代码为什么这样写，而不是复述它做了什么。

## 应该写

- 非显然的约束、边界条件、失败模式
- 与外部协议、格式、字段对应的原因
- 绕过某个坑的理由，以及不能随便改的地方
- 模块或复杂函数的整体意图

## 不要写

- 计划性、过程性注释：`// Step 1`、`// TODO: 后面再补`、`// 按方案实现`、`// 先这样`、`// 接下来做 X`
- 复述代码本身的注释：`// 设置 name`、`// 遍历数组`
- 与当前代码无关的说明、任务清单、PR 描述式内容
- 被注释掉的旧代码（直接删除，历史在 Git 里）
- 为了“看起来有注释”而加的填充注释

判断标准：注释描述的是**代码长期成立的事实**，不是本次改动的过程。注释默认用中文，除非该文件已有明确的英文注释风格。
